COMMERCEFABRIC

CommerceFabric is an Azure-hosted e-commerce platform built to demonstrate cloud-native and distributed-system architecture.

Architecture:
- Angular web frontend.
- Microsoft Entra ID for authentication.
- Azure API Management as an external API management layer.
- Ocelot API Gateway.
- Azure Kubernetes Service (AKS).
- Independently deployable ASP.NET Core User, Product, and Order services.
- Database-per-service architecture.
- PostgreSQL for user data.
- MySQL for product data.
- MongoDB for order data.
- REST for synchronous service communication.
- RabbitMQ and Azure Service Bus for asynchronous/event-driven communication.
- Redis caching.
- Polly for retry and transient-fault resilience.
- Microsoft Graph integration.
- Infrastructure work includes Bicep.

Order workflow:
- A successful order publishes an Order Created event to an Azure Service Bus Topic.
- The Product Service subscribes and asynchronously reduces product stock.
- Failed stock-processing messages can be moved to a dead-letter queue.
- The topic-based publish/subscribe model allows future services such as Payment and Notification services to subscribe without creating direct dependencies.

Product update/delete events:
- RabbitMQ and Azure Service Bus are both demonstrated.
- The Order Service consumes events to update or invalidate its Redis cache of product information.
- Both messaging technologies are intentionally included to demonstrate experience with self-hosted and Azure-managed messaging; a production system would typically standardise on one where appropriate.

The project demonstrates scalability, fault isolation, independent deployment, service ownership, API governance, resilience, caching, asynchronous workflows, and loose coupling.

Primary languages/technologies include C#, TypeScript, and Bicep.

HEARTHSTONE DECK PREDICTOR

A WPF plugin for Hearthstone Deck Tracker that predicts an opponent's likely deck in real time.

Purpose:
Returning Hearthstone players can find it difficult to keep up with a changing meta and recognise opposing archetypes. The plugin uses cards revealed during a match to progressively estimate the opponent's likely deck and strategy.

Architecture and behaviour:
- Integrates with Hearthstone Deck Tracker's internal API.
- Reacts to live game and opponent card-play events.
- Retrieves current Standard meta deck data from HSReplay.net at the start of a game.
- Stores deck information in memory for fast matching.
- Uses hash-based lookups and progressive filtering to eliminate incompatible decks as cards are revealed.
- Ranks remaining candidates to identify likely archetypes.
- Displays likely remaining cards.
- Displays predicted deck/archetype information.
- Surfaces matchup odds against the player's likely archetype.

The goal is to help players identify threats, understand the current meta, and make better-informed decisions during a match.
